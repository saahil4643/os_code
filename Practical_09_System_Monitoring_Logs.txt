PRACTICAL NO. 9: SYSTEM MONITORING AND LOG MANAGEMENT CONCEPTS IN LINUX

AIM
To study system performance monitoring and the examination of system log information in Linux.

REQUIREMENTS
1. Computer or laptop.
2. Kali Linux operating system.
3. Terminal application.
4. Basic knowledge of Linux commands.

THEORY
System monitoring is the observation of operating-system activity and resource utilisation. Common areas include processor load, memory use, disk capacity, running processes, uptime, and device activity. Monitoring helps administrators identify performance problems, unexpected behaviour, and shortages of system resources.

Linux provides command-line utilities for displaying current and historical system information. Some commands provide a snapshot, while others refresh continuously. Monitoring values should be interpreted in context. For example, high CPU or memory usage alone does not prove malicious activity.

Log management involves collecting, storing, reviewing, and preserving records generated by the operating system and applications. Logs may contain authentication events, service activity, warnings, errors, kernel messages, and other operational details. On many Linux distributions, text-based logs are stored under /var/log. Systems using systemd may also store journal entries that can be viewed with journalctl.

Logs are valuable in digital forensic investigations because they can help reconstruct system events and build timelines. However, log availability and retention depend on system configuration. Logs may rotate, be deleted, contain inaccurate timestamps, or be incomplete. Investigators should preserve relevant logs and compare them with other evidence such as file metadata, user records, and network information.

PROCEDURE
1. Open Kali Linux and start the terminal.
2. Run uptime to view system running time and load averages.
3. Run top to monitor live CPU, memory, and process activity; press q to exit.
4. Run ps aux to obtain a process snapshot.
5. Use free -h to examine RAM and swap usage.
6. Execute df -h to inspect disk capacity and available space.
7. List available log files using ls /var/log.
8. If the file exists, use tail /var/log/syslog to inspect recent entries.
9. Run journalctl -n 50 to view the latest 50 system journal entries.
10. Run dmesg to inspect kernel messages.
11. Use grep with a suitable pattern to search a log file.
12. Record the command, source, observation time, and relevant entries. Do not edit or delete original logs.

COMMANDS AND THEIR FUNCTIONS
1. top — Displays live processes and resource usage.
2. ps aux — Shows a detailed process snapshot.
3. free -h — Displays RAM and swap statistics.
4. df -h — Displays file-system capacity and usage.
5. uptime — Shows system uptime and load averages.
6. ls /var/log — Lists available system log files.
7. cat /var/log/syslog — Displays the syslog file, if available and readable.
8. tail /var/log/syslog — Displays the last lines of the syslog file.
9. journalctl — Displays systemd journal entries.
10. journalctl -n 50 — Displays the latest 50 journal entries.
11. dmesg — Displays kernel ring-buffer messages.
12. grep "pattern" logfile — Searches a log file for matching lines.

RESULT
System uptime, running processes, CPU and memory utilisation, disk usage, and available system log information were examined using Linux monitoring commands.

CONCLUSION
This practical demonstrated how Linux monitoring tools and logs provide information about system operation. These records can assist troubleshooting and forensic timeline development. Log interpretation requires attention to time settings, retention, completeness, and comparison with independent evidence.
